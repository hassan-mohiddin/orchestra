# Codex Adversarial Review

Target: branch diff against main
Verdict: needs-attention

No-ship: the focused LLD is internally inconsistent and specifies failure handling that can leave users in partially applied, hard-to-recover states while still allowing false-positive verification.

Findings:
- [high] Conflicting `pass_filenames` contract for commit-msg hook (docs/features/010-framework-detection-determinism.md:41-101)
  The spec gives mutually exclusive requirements: A1 defines `orchestra-commit-msg` with `pass_filenames: false`, while A12 and In-Scope item 1 call out `pass_filenames: true` for commit-msg. This makes implementation/test acceptance non-deterministic. If implementers follow the `true` path, extra matched filenames may be appended after the commit message file (as the doc itself warns elsewhere), which can change or break finalize-hook behavior.
  Recommendation: Pick one canonical value (consistent with Glossary/A1 intent), then update A12, Scope, snippet examples, and tests so only that contract can pass review.
- [high] Snippet emission behavior is contradictory (full-template-only vs tailored output) (docs/features/010-framework-detection-determinism.md:47-263)
  A3 states tailoring was removed and output is always the full snippet, and `_emit_full_snippet` repeats this. But In-Scope still requires tailoring to user settings. These are incompatible behaviors and will cause implementation and test drift around what install output should be in real repos.
  Recommendation: Choose one behavior (full snippet always, or tailored output), remove the opposite language everywhere, and add a deterministic output assertion in tests for each framework-detected path.
- [high] `--apply` has no rollback after external install failure, causing irreversible partial state (docs/features/010-framework-detection-determinism.md:303-390)
  The flow writes `.pre-commit-config.yaml` first, then runs `pre-commit install`. On install failure it returns non-zero without restoring the previous config. Because the same design also acknowledges PyYAML comment stripping, users can lose config comments/format and still fail installation, ending in a partially applied state with no automatic recovery.
  Recommendation: Treat `--apply` as a transaction: keep a pre-image backup and restore on install/verify failure, or delay committing config changes until install+verify succeed. Add explicit rollback tests for subprocess failure and verify failure.
- [high] `--verify` can return PASS for non-functional hooks due weak fingerprint heuristic (docs/features/010-framework-detection-determinism.md:50-365)
  Verification only checks for hook-file existence plus substring presence (`orchestra` or `generated by pre-commit`) anywhere in file content. A stale or custom script can satisfy these substrings without executing the expected orchestration path, leading to false PASS and silent policy bypass.
  Recommendation: Verify executable semantics, not just marker text: assert expected command patterns per stage (framework `hook-impl` invocation and/or explicit `python -m cli.lint` contract), and add negative tests where marker text exists but command wiring is wrong.

Next steps:
- Resolve spec contradictions (`pass_filenames` and tailoring behavior) before implementation proceeds.
- Add transactional rollback requirements and tests for `--apply` partial-failure paths.
- Strengthen `--verify` to validate hook execution intent, then add adversarial false-positive tests.
