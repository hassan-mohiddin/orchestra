## Problem Statement

orchestra v1.0–1.4 enforces docs-driven discipline via markdown rules auto-loaded into Claude's session prompt and a lint that checks marker-string presence. Two interlocking failures observed in 2026-05-06 sessions and reproduced in 2026-05-07:

1. **Rule drift under context rot.** `.claude/rules/*.md` are loaded once at session start. As session context grows past ~50k tokens, instruction adherence decays measurably (Liu et al. "Lost in the Middle" 2024; Chroma "Context Rot" 2025; Anthropic "Effective Context Engineering" 2026). Rules are technically present but functionally forgotten. The agent acknowledges rules and violates them in the same response (Mu et al. 2024; arXiv 2407.08440).
2. **Cargo-cult spec review.** Gate 3's "Iteration N spec review — X/4 gates pass" Changelog marker is enforced by string-presence regex. Author and reviewer are the same agent context. Marker presence ≠ review substance. In 2026-05-07 session, agent added markers without running review. Pattern named in compliance-theater literature (Ken Muse) and policy-as-code field (OPA / Conftest).

These failures are STRUCTURAL, not behavioral. No amount of additional markdown discipline fixes them. The architecture must move from "rule is described where it sits" to "rule is enforced where it acts."

Secondary problems exposed during root-cause analysis:

3. **No backward-flow primitive.** When phase X (e.g. execute) reveals a gap in phase Y (e.g. design), no formal mechanism exists to halt X, return to Y, resolve, and resume X. Pattern degrades to "patch with new BUG-NNN" instead of "rewind to design."
4. **No learning loop.** Violations get logged (or not) but produce no captured rule-amendment. Same violation recurs.
5. **No interview discipline.** Agent makes silent decisions when uncertain instead of halting and asking. Same anti-pattern as marker-without-review.
6. **Implementation Sync Gate is self-attestation.** "Re-read the doc and log deviations" depends on the same agent that wrote the deviation noticing it (PactFlow 2024 — drift detection requires execution, not re-reading).

## Scope

### In Scope (5 Pillars)

**Pillar 1 — Memory Architecture (4-Placement)**

| Placement | What goes there | Mechanism |
|---|---|---|
| (a) System prompt | Identity + gate-name index ≤500 tokens behind one cache breakpoint | `.claude/CLAUDE.md` trimmed; user owns project-specific addendum |
| (b) UserPromptSubmit hook | Short imperative reminders ≤80 tokens, conditional on prompt surface form | orchestra-shipped hook with keyword match (`bug:|fix:|docs/`); per-hook cooldown 300s |
| (c) Fresh-context subagent | Discipline-critical actions (Gate 3 review; Gate 0 high-stakes interviews) | Claude Code Agent tool (general-purpose); orchestra ships default prompt template |
| (d) PreToolUse JIT disk read | Rule body injected just before action (e.g. read `.claude/orchestra/rules/documentation-gate.md` before `git commit`) | orchestra-shipped hook; reads matching rule file into next-turn context only |

Deepest principle (replaces "markdown discipline > code"): **Place rule next to action; don't remind model to remember it.**

**Pillar 2 — Gate Redesign**

| Gate | v1.4 status | v1.5 redesign |
|---|---|---|
| Gate 0 (Interview) | did not exist | NEW — fires at every phase transition; `orchestra:checkpoint` skill default; fresh subagent for high-stakes (entering execute, pre-commit, pre-merge) |
| Gate 1 (Discovery) | "STOP on every observation" — too eager | KEEP, tighten trigger language to "fires on confirmed defect, not suspected"; investigation→BUG promotion path canonical, not override |
| Gate 2 (Design) | KEEP | unchanged — validated by Stripe/Google/Uber practice |
| Gate 3 (Spec Review) | self-attestation marker | REBUILD — fresh-context subagent + executable attestation lint; no in-doc marker |
| Gate 4 (Commit Refs) | KEEP | unchanged — already non-self-attestation, hook-enforced |
| Gate 5 (Impl Sync) | self-attestation re-read | REBUILD — 7 mechanical drift checks; no author re-read |

Phase transition table (Gate 0 trigger map):

| Transition | Mechanism |
|---|---|
| Brainstorm → Design (about to create `docs/features/NNN-*.md`) | `orchestra:checkpoint` skill — lists open brainstorm questions |
| Design → Plan (about to create `docs/plans/YYYY-MM-DD-*.md`) | `orchestra:checkpoint` — asks "all design decisions captured?" |
| Plan → Execute (about to Edit/Write to `apps/`/`packages/` or equivalent) | Fresh subagent reads plan + current code state; returns gaps |
| Execute → Verify (about to run `make check` or commit) | `orchestra:checkpoint` — lists deviations not yet logged |
| Self-prompted at any decision point | `orchestra:checkpoint` — agent invokes itself |

7 Gate-5 mechanical drift checks (replaces author re-read):

| # | Check | When fires |
|---|---|---|
| G5.1 | Every `Refs:` target file in commit body resolves to a real path in repo | commit-msg hook |
| G5.2 | Every file path in LLD's `## File Structure` or `## Files` section resolves (glob or exact) | lint --doc |
| G5.3 | Status field consistent with commit prefix (feat: → Refs'd Status ∈ {Implemented, Verified}; fix: → Refs'd Status ∈ {Fix Applied, Verified}) | commit-msg hook |
| G5.4 | Bug doc iteration log has an entry for the current iteration before `fix:` commit | commit-msg hook |
| G5.5 | Refs'd doc has a valid `docs/reviews/<doc-id>-r<N>.review.yaml` attestation (Gate 3 linkage) | commit-msg hook |
| G5.6 | Mermaid blocks parse | already exists (lint --mermaid) |
| G5.7 | No placeholder text (TBD / TODO: / [fill in]) in canon docs | already exists (lint --doc) |

AST-level drift (function-signature comparison) DEFERRED to v1.6+ pending observed incident; tree-sitter / language-specific is its own LLD.

**Pillar 4 — Lesson Capture (Capture-Only)**

Mechanism (replay-prevention READ side deferred to v1.6+):

```
1. User observes violation (or hook detects); flags to agent
2. Agent invokes orchestra:violation-noted skill
3. Skill prompts agent + user co-author template:
   - violation_type: gate_skipped | rule_violated | silent_decision | other
   - trigger: <specific situation that led to it>
   - what_happened: <one paragraph>
   - root_cause: <one paragraph>
   - prevention: <specific rule that would catch this next time>
   - related_rule_update: <link to rule amendment if needed>
4. User signs off (mandatory — prevents agent self-canonization)
5. Skill writes to .claude/orchestra/lessons/YYYY-MM-DD-<short>.md
6. Skill appends event to .claude/orchestra/state/metrics.jsonl
```

Critical safeguard: user sign-off mandatory before lesson becomes canon. Mitigates "cascading hallucination" failure mode (DEV 2024; arXiv 2603.07670).

**Pillar 5 — Supersession + Backward Flow**

Forward order is mandatory; backward iteration is implemented as forward supersession (Roll-forward pattern: Redgate, Atlas, Temporal saga).

8-step backward-flow primitive:

```
1. Agent in phase X discovers gap in phase Y artifact (e.g. executing reveals LLD missing edge case)
2. Interview Gate fires: agent declares "halting X, returning to Y because <gap>"
   → Logged as metrics.jsonl event: phase_halt
3. Agent locates current canon artifact (e.g. LLD-NNN-r1)
4. Agent creates supersession draft: LLD-NNN-r2.md with frontmatter:
     > Supersedes: docs/features/LLD-NNN-r1.md
     > Status: Draft
5. Agent + user resolve gap in r2 draft
6. r2 spec-reviewed (Gate 3) — fresh subagent attestation at docs/reviews/LLD-NNN-r2.review.yaml
7. r2 attestation pass → r2 promoted to canon (Status: Approved or higher); r1 marked Status: Superseded
   → Lint blocks any new Refs: pointing to r1 (must use r2)
8. Agent resumes phase X; X's gates re-pass on top of r2 (not r1)
```

Supersession scope: applies to reviewed canon types (Feature LLD, ADR, Bug Report, Design Doc, Postmortem, Runbook). Plans + investigations stay mutable (their lifecycle is short-lived; supersession overhead would not pay).

Discoverability: r1 stays in repo with Status: Superseded + footer auto-appended `Superseded by: docs/features/LLD-NNN-r2.md`. Bidirectional link via lint enforcement.

## Design

### Hook stack composition

Order: orchestra-first (discipline before customization). User hooks layer on after.

Ownership:
- orchestra hooks ship via plugin manifest (auto-install on plugin enable)
- User opts-out per-hook in `.claude/orchestra.json` `disabled_hooks: []`
- User adds own hooks via Claude Code native `settings.json` / `settings.local.json`
- orchestra hooks namespaced (`orchestra/pre-tool-use/edit-doc`)

Cooldowns:
- orchestra ships sensible defaults per-hook (300s for context-injection; 0 for enforcement)
- User overrides per-hook in `orchestra.json`

Example config:

```yaml
# .claude/orchestra.json (excerpt)
hooks:
  pre_tool_use:
    edit_canon_doc:
      enabled: true
      cooldown_seconds: 0
      injects_rule: documentation-gate
    edit_code_no_design:
      enabled: true
      cooldown_seconds: 0
      blocks_action: true
    pre_commit_drift_check:
      enabled: true
      cooldown_seconds: 0
      runs: cli.lint --pre-commit
  post_tool_use:
    write_doc_attestation_log:
      enabled: true
      cooldown_seconds: 0
      writes: .claude/orchestra/state/metrics.jsonl
  user_prompt_submit:
    inject_active_doc_context:
      enabled: true
      cooldown_seconds: 300
      max_per_session: 12
disabled_hooks: []
```

### Attestation YAML schema v1.0

File: `docs/reviews/<doc-id>-r<N>.review.yaml`

```yaml
schema_version: "1.0"
doc_subject:
  path: docs/features/005-v1.5-enforcement-core.md
  content_hash: sha256:abcd1234...
  iteration: 1
reviewer:
  identifier: "subagent:general-purpose"   # or "skill:superpowers:requesting-code-review" etc
  invoked_at: 2026-05-07T14:23:00Z
  context_isolation: fresh_subagent        # or in_session (degraded)
gates:
  completeness:
    verdict: pass                          # pass | fail
    findings: []                           # list of strings
  evidence:
    verdict: pass
    findings: []
  clarity:
    verdict: pass
    findings: []
  consistency:
    verdict: pass
    findings: []
overall_verdict: pass                      # pass | fail | conditional_pass
required_followup: []                      # populated if conditional_pass
notes: |
  Free-form prose if reviewer adds context.
```

orchestra owns the schema (rigid). User reviewer plugins (post LLD-006 registry) must emit conformant YAML.

### Metrics JSONL schema

File: `.claude/orchestra/state/metrics.jsonl` (append-only)

6 event types:

| Event | Fields |
|---|---|
| `gate_violation` | gate, doc, details |
| `attestation_written` | doc, review_path, verdict |
| `session_start` | (timestamp only) |
| `session_end` | duration_minutes |
| `corpus_count` | docs_total |
| `handoff_failure` | reason, prior_session_id |

Example:
```json
{"ts":"2026-05-07T14:23:00Z","event":"gate_violation","gate":"3","doc":"docs/features/005.md","details":"no attestation"}
{"ts":"2026-05-07T14:23:01Z","event":"attestation_written","doc":"docs/features/005.md","review_path":"docs/reviews/005-r1.review.yaml","verdict":"pass"}
```

L0→L1 upgrade signal computed from this log:
- Gate-violation rate per 4-hour session > 0.5
- corpus_count > 200
- handoff_failures > 1/week

When ≥2 fire concurrently, surface L1-upgrade prompt.

### Migration mechanics (v1.4 → v1.5)

Opt-in only. User invokes `orchestra:upgrade` skill (interactive) or `python -m cli.upgrade --to-v1.5 --trim-rules` (scriptable).

Per-rule migration:
```
.claude/rules/documentation-gate.md (5kb, auto-loaded by Claude Code)
    ↓ orchestra:upgrade
.orchestra-backup/rules/documentation-gate.md (full original, backup)
.claude/rules/documentation-gate.md (≤300 token stub: 1-line summary + pointer)
.claude/orchestra/rules/documentation-gate.md (full body, NOT auto-loaded)
.claude/orchestra.json hooks.PreToolUse += rule mapping
```

Pre-flight checks before migrate:
- Working tree clean
- `.orchestra-backup/` doesn't exist (or `--force`)
- v1.4 detection (read `.claude/orchestra.json` version field)

Rollback: `cli.upgrade --rollback` restores from `.orchestra-backup/`.

## Edge Cases

- **Migration on dirty working tree.** `cli.upgrade` refuses; user must commit/stash first. Pre-flight check.
- **User runs `--rollback` after committing v1.5 changes.** Restores backup but doesn't undo commits — user warned, told to use `git revert`.
- **Reviewer subagent times out.** orchestra:spec-review surfaces error; lint treats as failed gate (no attestation = fail). User can re-invoke.
- **Reviewer emits non-conformant YAML.** Lint rejects; surfaces YAML diff vs schema; attestation NOT counted as pass.
- **Two concurrent supersessions of same doc** (LLD-NNN-r2 and LLD-NNN-r3 both drafted simultaneously). Lint detects via Supersedes link analysis; surfaces conflict; user resolves manually before either is reviewed.
- **Lesson written, user never signs off.** Lesson stays in `.claude/orchestra/lessons/` with `signed_off: false` field; lint excludes from canon-pulled context. Stale lessons (>30 days unsigned) flagged for cleanup.
- **Hook fires but rule body file missing.** Hook logs warning to metrics.jsonl (event type: `hook_misfire`); does NOT block action — fail-open with telemetry rather than fail-closed without rule.
- **CLAUDE.md trim leaves user-added project content unrelated to orchestra.** `cli.upgrade` only modifies `.claude/rules/*.md` orchestra-shipped files; user content in CLAUDE.md preserved.
- **Project never had `.claude/rules/` (fresh orchestra adopter).** `cli.upgrade` skips trim; sets up new architecture from scratch via `cli.init` integration.
- **User disables Gate 0 (Interview) in `disabled_hooks`.** Allowed but lint warns; surfaces a lesson candidate ("you disabled Gate 0; if a future violation traces here, this is why").

## Security

- **Attestation file integrity.** YAML signed only via `content_hash` field (sha256 of doc subject); no cryptographic signature. Trust model: file in repo + git history. Future hardening (sigstore / in-toto) deferred to v2.0.
- **Lesson templates user-controlled.** Sign-off requirement prevents agent self-canonization; user is the trust anchor.
- **`.orchestra-backup/` exposes pre-trim rule bodies in repo.** Add to default `.gitignore` via `cli.upgrade` to prevent accidental commit; user can opt-in to commit if they want backup in git history.
- **Hook execution.** orchestra hooks are user-readable Bash/Python scripts shipped via plugin; user can audit and disable per-hook. No remote-fetched code.
- **JIT rule injection from disk.** PreToolUse hooks read files only from `.claude/orchestra/rules/` (orchestra-namespaced); not arbitrary paths. Path traversal blocked by basename validation.
- **Subagent dispatch.** Uses Claude Code's Agent tool — same trust model as user invoking subagent directly. No new capability surface.
