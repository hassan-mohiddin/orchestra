## Glossary (defined once)

- **canon** — reviewed, committed doc under v1.5 process whose Status is Implemented / Verified / Approved / Current. Lives at `docs/features/`, `docs/bugs/`, `docs/adr/`, `docs/design/`, `docs/postmortems/`, `docs/runbooks/`. Distinguished from **scratch** (`docs/investigations/` — never reviewed) and **mutable** (`docs/plans/` — reviewed but short-lived, in-place edits permitted).
- **attestation** — YAML file at `docs/reviews/<doc-id>-r<N>.review.yaml` produced by Gate 3 reviewer; hash-bound to subject doc; conformant to schema v1.0 (`.claude/orchestra/schema/review.schema.yaml`).
- **canon doc edit detector** — PreToolUse hook firing on Edit/Write to canon-path file; triggers Interview Gate (Gate 0).
- **iteration** — revision number on canon docs (r1, r2, ...). Each revision is a separate file with `Supersedes:` link to prior.

## Problem Statement

orchestra v1.0–1.4 enforces docs-driven discipline via markdown rules auto-loaded into Claude's session prompt and a lint that checks marker-string presence. Two interlocking failures observed in 2026-05-06 sessions and reproduced in 2026-05-07:

1. **Rule drift under context rot.** `.claude/rules/*.md` are loaded once at session start. As session context grows past ~50k tokens, instruction adherence decays measurably (Liu et al. "Lost in the Middle" arXiv 2307.03172, TACL 2024; Chroma "Context Rot" 2025; Anthropic "Effective Context Engineering" 2026). Rules are technically present but functionally forgotten. Empirical study (arXiv 2411.10541, 2024) confirms format choice causes 10–40% performance variance; instruction-following decays smoothly with input length.
2. **Cargo-cult spec review.** Gate 3's "Iteration N spec review — X/4 gates pass" Changelog marker is enforced by string-presence regex. Author and reviewer are the same agent context. Marker presence ≠ review substance. In 2026-05-07 session, agent (this author) added markers without running review. Pattern named in compliance-theater literature (Ken Muse "Security Theater") and replaced in policy-as-code field (OPA / Conftest where rule IS the executor).

These failures are STRUCTURAL, not behavioral. No amount of additional markdown discipline fixes them. The architecture must move from "rule is described where it sits" to "rule is enforced where it acts."

Secondary problems exposed during root-cause analysis:

3. **No backward-flow primitive.** When phase X (e.g. execute) reveals a gap in phase Y (e.g. design), no formal mechanism exists to halt X, return to Y, resolve, and resume X. Pattern degrades to "patch with new BUG-NNN" instead of "rewind to design."
4. **No learning loop.** Violations get logged (or not) but produce no captured rule-amendment. Same violation recurs.
5. **No interview discipline.** Agent makes silent decisions when uncertain instead of halting and asking. Same anti-pattern as marker-without-review.
6. **Implementation Sync Gate is self-attestation.** "Re-read the doc and log deviations" depends on the same agent that wrote the deviation noticing it (PactFlow 2024 — drift detection requires execution, not re-reading).

Replaces "Markdown discipline > code" with: **Place rule next to action; don't remind model to remember it.**

**Pillar 4 — Lesson Capture (Capture-Only)**

Mechanism (replay-prevention READ side deferred to v1.6+):

```
1. User observes violation (or hook detects); flags to agent
2. Agent invokes orchestra:violation-noted skill
3. Skill prompts agent + user co-author template:
   - violation_type: gate_skipped | rule_violated | silent_decision | other
   - trigger: <specific situation that led to it>
   - what_happened: <one paragraph>
   - root_cause: <one paragraph>
   - prevention: <specific rule that would catch this next time>
   - related_rule_update: <link to rule amendment file path; null if none>
   - signed_off: false (initially)
4. User reviews + signs off (sets signed_off: true)
5. Skill writes to .claude/orchestra/lessons/YYYY-MM-DD-<short>.md (markdown body + YAML frontmatter)
6. Skill appends event to .claude/orchestra/state/metrics.jsonl
```

Critical safeguard: user sign-off mandatory before lesson becomes canon. Mitigates "cascading hallucination" failure mode (industry write-up: DEV.to "Your AI agent is confidently lying").

Stale lessons (signed_off: false for >30 days) flagged for cleanup. 30-day rationale: matches typical sprint retrospective cadence (Atlassian Kanban guidance); not strictly evidence-based, accepted heuristic.

Lesson file format: **markdown body + YAML frontmatter** per Round 5 research (Cursor MDC, Agent Skills open spec convergence). Frontmatter holds violation_type, trigger, signed_off; body holds what_happened, root_cause, prevention, related_rule_update prose.

**Pillar 5 — Supersession + Backward Flow**

Forward order is mandatory; backward iteration is implemented as forward supersession (Roll-forward pattern: Redgate, Atlas, Temporal saga). Old revisions retain `Status: Superseded` and stay visible (Karpathy: visible markdown beats opaque store).

8-step backward-flow primitive:

```
1. Agent in phase X discovers gap in phase Y artifact (e.g. executing reveals LLD missing edge case)
2. Interview Gate fires: agent declares "halting X, returning to Y because <gap>"
   → Logged as metrics.jsonl event: phase_halt
3. Agent locates current canon artifact (e.g. LLD-NNN-r1)
4. Agent creates supersession draft: LLD-NNN-r2.md with frontmatter:
     > Supersedes: docs/features/LLD-NNN-r1.md
     > Iteration: 2
     > Status: Draft
5. Agent + user resolve gap in r2 draft
6. r2 spec-reviewed (Gate 3) — fresh subagent attestation at docs/reviews/LLD-NNN-r2.review.yaml
7. r2 attestation pass → r2 promoted to canon (Status: Approved or higher); r1 marked Status: Superseded with footer:
     > Superseded by: docs/features/LLD-NNN-r2.md
     > Reason: <one-line summary>
   → Lint blocks any new Refs: pointing to r1 (must use r2)
8. Agent resumes phase X; X's gates re-pass on top of r2 (not r1)
```

Supersession scope: applies to canon types (Feature LLD, ADR, Bug Report, Design Doc, Postmortem, Runbook). Plans + investigations stay mutable.

This LLD-005-r2 itself dogfoods the supersession primitive — see frontmatter `Supersedes:` field.

## Design

### File Format Choice (Round 5 research validation)

orchestra v1.5 uses three formats per content-shape rule (validated 2026-05-07):

| File type | Format | Citation |
|---|---|---|
| Design docs (LLD/ADR/BUG/Design/Postmortem/Runbook) | Markdown + optional YAML frontmatter | AGENTS.md (Linux Foundation Dec 2025); llms.txt (Answer.AI Sep 2024); Cursor MDC; Cline rules |
| Rules (`.claude/orchestra/rules/*.md`) | Markdown body + YAML frontmatter | Cursor MDC reference; Agent Skills open spec convergence |
| Attestations | YAML sidecar | improvingagents.com nested-retrieval benchmark (YAML 62.1% > markdown 54.3% on GPT-5 frontier) |
| Metrics log | JSONL | Industry standard append-only event log |
| Lessons | Markdown + YAML frontmatter | Same as design docs (prose-dominant) |
| STANDARDS.md / philosophy / README | Markdown | Same |

Critical principle: **content-shape rule** — prose-dominant + judgment-needed → markdown; schema-fixed + machine-validated → YAML/JSONL. Unifying everything onto one format breaks the system (markdown destroys machine-validatable contracts; pure structured destroys prose nuance).

Rule-file shape (NEW vs r1 — r1 had bare markdown):

```markdown
---
gate: documentation-gate
applies_when:
  pre_tool_use:
    - tool: Edit
      path_glob: ["docs/features/**/*.md", "docs/bugs/**/*.md", ...]
    - tool: Bash
      command_glob: ["git commit*"]
description: Documentation gate enforcement at canon-doc edits + commits
inject_max_tokens: 5000
---

# Documentation Gate (full body)

Gate 1 — Discovery...
Gate 2 — Design...
[full prose continues]
```

Frontmatter holds activation conditions (Cursor MDC pattern); body holds rule prose. PreToolUse hook reads frontmatter to decide whether to inject body.

### Hook stack composition

Order: orchestra-first (discipline before customization). User hooks layer on after.

Ownership precedence (resolves r1 ambiguity):
- orchestra hooks ship via plugin manifest (auto-install on plugin enable)
- User opts-out per-hook in `.claude/orchestra.json` `disabled_hooks: ["pre-tool-use:edit-canon-doc"]`
- User adds own hooks via Claude Code native `settings.json` / `settings.local.json`
- **Precedence:** `disabled_hooks` field wins; `enabled: true` per-hook is the orchestra-shipped default. If hook is in `disabled_hooks`, it does not fire regardless of `enabled` field.
- orchestra hooks namespaced (`orchestra/pre-tool-use/edit-canon-doc`) for discoverability

Cooldowns: orchestra ships sensible defaults per-hook; user overrides per-hook.

```yaml
# .claude/orchestra.json (excerpt)
hooks:
  pre_tool_use:
    edit_canon_doc:
      enabled: true
      cooldown_seconds: 0          # enforcement = every fire
      injects_rule: documentation-gate
    edit_code_no_design:
      enabled: true
      cooldown_seconds: 0
      blocks_action: true
    pre_commit_drift_check:
      enabled: true
      cooldown_seconds: 0
      runs: cli.lint --pre-commit
  post_tool_use:
    write_doc_attestation_log:
      enabled: true
      cooldown_seconds: 0
      writes: .claude/orchestra/state/metrics.jsonl
  user_prompt_submit:
    inject_active_doc_context:
      enabled: true
      cooldown_seconds: 300        # context-injection = 5min cooldown
      max_per_session: 12
disabled_hooks: []                 # user opt-out list
```

### Attestation YAML schema v1.0

File: `docs/reviews/<doc-id>-r<N>.review.yaml`. Schema lives at single canonical path: `.claude/orchestra/schema/review.schema.yaml`. Tests reference this schema. Lint loads it.

```yaml
schema_version: "1.0"
doc_subject:
  path: docs/features/005-v1.5-enforcement-core-r2.md
  content_hash: sha256:<64 hex chars>             # full sha256, no ellipsis
  iteration: 2
reviewer:
  identifier: "subagent:general-purpose"          # or "subagent:codex-rescue" or "skill:<plugin>:<skill>"
  invoked_at: 2026-05-07T16:59:38Z
  context_isolation: fresh_subagent               # MUST be fresh_subagent; in_session is rejected
gates:
  completeness:
    verdict: pass | fail
    findings: []
  evidence:
    verdict: pass | fail
    findings: []
  clarity:
    verdict: pass | fail
    findings: []
  consistency:
    verdict: pass | fail
    findings: []
overall_verdict: pass | fail | conditional_pass
required_followup: []
notes: |
  Free-form prose if reviewer adds context.
```

orchestra owns the schema (rigid). User reviewer plugins (post LLD-006 registry) must emit conformant YAML.

### Metrics JSONL schema

File: `.claude/orchestra/state/metrics.jsonl` (append-only). 6 event types:

| Event | Fields |
|---|---|
| `gate_violation` | gate, doc, details |
| `attestation_written` | doc, review_path, verdict |
| `session_start` | (timestamp only) |
| `session_end` | duration_minutes |
| `corpus_count` | docs_total |

L0→L1 upgrade signal: when ≥2 of {gate-violation rate >0.5/4hr session, corpus_count >200, handoff_failures >1/week} fire concurrently, lint surfaces upgrade prompt. Thresholds are heuristic seed values; v1.6 will revisit based on observed JSONL data.

### Migration mechanics (v1.4 → v1.5) — skill ↔ CLI relationship

`orchestra:upgrade` skill is the interactive UI. Skill flow:
1. Skill prompts user with confirmation + lists what will change
2. Skill builds CLI argument list from user answers
3. Skill invokes `python -m cli.upgrade --to-v1.5 [flags]` as subprocess
4. Skill surfaces CLI output to user

`cli.upgrade` is the single source of truth for migration logic. Skill never duplicates logic.

CLI flags:
- `--to-v1.5` (required — explicit version target)
- `--trim-rules` (move rule bodies to `.claude/orchestra/rules/`)
- `--force` (bypass pre-flight checks; required if `.orchestra-backup/` exists or working tree dirty)
- `--rollback` (restore from `.orchestra-backup/`)
- `--dry-run` (print diff without modifying)

Per-rule migration:
```
.claude/rules/documentation-gate.md (5kb, auto-loaded by Claude Code)
    ↓ orchestra:upgrade
.orchestra-backup/rules/documentation-gate.md (full original, backup)
.claude/rules/documentation-gate.md (≤300 token stub: 1-line summary + pointer)
.claude/orchestra/rules/documentation-gate.md (full body + YAML frontmatter, NOT auto-loaded)
.claude/orchestra.json hooks.PreToolUse += rule mapping
```

Pre-flight checks (CLI refuses unless `--force`):
- Working tree clean
- `.orchestra-backup/` doesn't exist
- v1.4 detection (read `.claude/orchestra.json` version field)

## Edge Cases

- **Migration on dirty working tree.** `cli.upgrade` refuses; user must commit/stash first OR pass `--force`. Pre-flight check.
- **User runs `--rollback` after committing v1.5 changes.** Restores `.orchestra-backup/` but doesn't undo commits — user warned, told to use `git revert`.
- **Reviewer subagent times out.** orchestra:spec-review surfaces error; lint treats as failed gate (no attestation = fail). User can re-invoke.
- **Reviewer emits non-conformant YAML.** Lint rejects; surfaces YAML diff vs schema; attestation NOT counted as pass.
- **Subagent vs author Gate 3 disagreement.** Subagent verdict = fail; author believes attestation is wrong. Resolution: surface attestation to user; user decides:
  - Accept subagent verdict → write r2 supersession addressing required_followup
  - Override subagent → user adds `notes: { user_override: true, reason: <text> }` field to attestation; lint accepts override but logs `gate_3_user_override` event to metrics.jsonl for audit
  - Re-run subagent with refined prompt → new attestation file at `docs/reviews/<doc-id>-r<N>-iteration2.review.yaml`
- **content_hash mismatch (doc edited after attestation).** Lint detects via fresh hash compute vs stored value; fails with "doc edited after attestation; re-run review" message. Mitigation: attestation regenerated by re-invoking orchestra:spec-review.
- **Concurrent attestations of same iteration.** Two agents writing to same `docs/reviews/<doc-id>-r<N>.review.yaml` simultaneously: orchestra writes attestation atomically via `os.replace` after temp-file write. If two writes interleave, last-writer-wins on the file; metrics.jsonl logs both attempts. User reviews log.
- **Two concurrent supersessions of same doc** (LLD-NNN-r2 and LLD-NNN-r3 both drafted simultaneously). Lint detects via Supersedes link analysis; surfaces conflict; user resolves manually before either is reviewed.
- **Lesson written, user never signs off.** Lesson stays in `.claude/orchestra/lessons/` with `signed_off: false` field; lint excludes from canon-pulled context. Stale lessons (>30 days unsigned) flagged for cleanup.
- **Hook fires but rule body file missing.** Hook logs warning to metrics.jsonl (event type: `hook_misfire`); does NOT block action — fail-open with telemetry rather than fail-closed without rule.
- **CLAUDE.md trim leaves user-added project content unrelated to orchestra.** `cli.upgrade` only modifies `.claude/rules/*.md` orchestra-shipped files; user content in CLAUDE.md preserved.
- **Project never had `.claude/rules/` (fresh orchestra adopter).** `cli.upgrade` skips trim; sets up new architecture from scratch via `cli.init` integration.
- **User disables Gate 0 (Interview) in `disabled_hooks`.** Allowed but lint warns; surfaces a lesson candidate ("you disabled Gate 0; if a future violation traces here, this is why").

## Security

- **Attestation file integrity.** YAML signed only via `content_hash` field (sha256 of doc subject); no cryptographic signature. Trust model: file in repo + git history. Future hardening (sigstore / in-toto) deferred to v2.0.
- **Lesson templates user-controlled.** Sign-off requirement prevents agent self-canonization; user is the trust anchor.
- **`.orchestra-backup/` exposes pre-trim rule bodies in repo.** Add to default `.gitignore` via `cli.upgrade` to prevent accidental commit.
- **Hook execution.** orchestra hooks are user-readable Bash/Python scripts shipped via plugin; user can audit and disable per-hook.
- **JIT rule injection from disk.** PreToolUse hooks read files only from `.claude/orchestra/rules/` (orchestra-namespaced); not arbitrary paths. Path traversal blocked by basename validation.
- **Subagent dispatch.** Uses Claude Code's Agent tool — same trust model as user invoking subagent directly.
